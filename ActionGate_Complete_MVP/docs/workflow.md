# Development Workflow

## Working loop
1. Pick one small issue from `docs/issues.md`.
2. Read the relevant specification and tests.
3. Implement the smallest change.
4. Add or update tests before relying on the feature.
5. Run `python -m pytest`.
6. Manually test the relevant demo path.
7. Update docs if behaviour or assumptions changed.
8. Mark the issue done only when evidence exists.

## Safety rules
- Do not implement several security-sensitive modules in one untested jump.
- Do not add AI until deterministic validation, policy, and impact calculation work.
- Never execute arbitrary SQL generated by an AI model.
- Do not mutate data before final authorization and impact revalidation.
- Failed validation, missing approval, stale approval, or audit errors must not silently permit an action.
- Use only fictional seed data.

## Demo readiness
For each demo scenario, keep a repeatable input and expected outcome. Show real application results, not fabricated screenshots. Be honest about features that are planned but not implemented.
